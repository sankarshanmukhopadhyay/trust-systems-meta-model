# TSMM v0.14.0

## Release name

**A2A Binding and Agent Interaction Completion**

## Summary

v0.14.0 completes the Agent Interaction Extension introduced in v0.13.0 and delivers
the A2A protocol binding. Three abstractions deferred from v0.13.0 — `InteractionTask`,
`ContentProvenancePolicy`, and `ObservabilityMode` — land in this release following a
boundary investigation that confirmed each warrants a distinct schema object. The full
ten-abstraction extension is now available for implementer use, and the machine-readable
A2A binding maps all ten against A2A protocol concepts.

The InteractionTask investigation found that `ExecutionContext` + lifecycle event
composition does not cover bounded work-in-progress semantics: ExecutionContext is
flat and per-evaluation, lifecycleEvent has no status tracking or artifact accumulation,
and Action is a single act rather than a container. InteractionTask is warranted and
distinct.

No core model changes. The effect-centered backbone and existing extension architecture
are unchanged.

## Why this matters

**InteractionTask** closes the gap between knowing a session is in progress and knowing
what work is happening within it. The seven-state status machine makes mid-task
governance events — particularly `auth-required` — traceable to their originating
AuthorizationCheckpoint and resolvable through the TSMM trust decision chain.

**ContentProvenancePolicy** makes payload governance explicit at the abstraction layer.
Agents that are authorized to exchange content are not automatically authorized to
exchange unverified, unsanitized, or unattributed content of any modality. The policy
makes that distinction machine-readable and auditable.

**ObservabilityMode** makes a structural governance gap explicit: the delivery model
of a channel determines what a governance system can observe, and that determination
is not a deployment choice — it is a structural property that requires compensating
controls. Documenting that gap is the first step to governing it.

**The A2A binding** is the primary integrative deliverable of this two-release arc.
It maps all ten TSMM agent interaction abstractions to A2A protocol concepts, explains
three abstractions that TSMM introduces for governance purposes that A2A has no explicit
schema counterpart for (`OpacityBoundary`, `PeerTrustRelation`, and `ContentProvenancePolicy`
against the Message/Artifact/Part model), and characterises the relationship between
the two layers so implementers understand what each is doing.
