# TSMM v0.21.0 - Executable Binding Assurance and Catalog Completeness

**Release date:** 2026-06-23  
**Status:** Additive assurance release

## Executive summary

TSMM v0.21.0 makes the published binding and graph catalog an enforceable repository contract. The release closes the gap between documented comparison surfaces and the artifacts validated in CI: every published binding is now contract-bearing and discoverable by the validator, and every published TSMM graph is subject to semantic relationship checks.

## What changed

- Aligned public release navigation, roadmap, documentation metadata, and schema identifiers to v0.21.0.
- Extended the binding schema to represent TSMM extension-layer types and mapping semantics used by published agent and assurance bindings.
- Added complete A2A and OASF binding contracts, maturity declarations, and constraint sets.
- Aligned human-readable binding statuses with machine-readable maturity declarations.
- Replaced incomplete hard-coded binding and graph validator catalogs with deterministic artifact discovery.
- Added binding conformance vectors for contract completeness and mapping vocabulary.
- Added a pinned, repository-owned validation dependency manifest used by local and CI validation.

## Governance impact

Binding publication now carries explicit authority boundaries. A published mapping must state what it guarantees, what it cannot establish, which operational inferences are prohibited, and which artifacts support review. This prevents discovery, publication, or a schema-valid descriptor from being misrepresented as delegated authority, runtime authorization, or independently proven assurance.

## Compatibility and migration

This is an additive release. Existing model instances remain valid. Binding authors should add a `bindingContract`, a constraint set, and a `maturity` declaration to any new binding. Existing automation should use the repository validation commands or the CI workflow rather than maintaining local artifact lists.
