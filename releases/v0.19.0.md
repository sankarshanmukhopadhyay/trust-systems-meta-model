# TSMM v0.19.0 — Agent Discovery, Capability Negotiation, and Task Evidence Readiness

## Executive summary

TSMM v0.19.0 is an enterprise-readiness release for agentic trust systems. It converts A2A-class interaction patterns into reusable TSMM governance surfaces for discovery, capability negotiation, extension governance, task evidence, descriptor integrity, and runtime auditability.

The release does not turn TSMM into an agent protocol. It does something more durable: it identifies the governance invariants that any agent interaction ecosystem needs if discovery, authorization, task execution, and evidence production are going to be inspectable across organizational boundaries.

## Business value

Organizations evaluating agent ecosystems need more than working message exchange. They need assurance that agents are discovered through legitimate sources, that descriptors are fresh and integrity-bound, that advertised capabilities are not confused with authorized capabilities, that required extensions are negotiated explicitly, and that task state transitions produce evidence suitable for audit, review, and redress.

v0.19.0 addresses that adoption gap by making those surfaces explicit and machine-verifiable.

## Major additions

### 1. Discovery Governance Model

New artifacts:

- `docs/model/discovery-governance.md`
- `schemas/tsmm-discovery-governance.schema.json`
- `examples/agent-discovery-governance-instance.json`
- `validation/test_vectors/valid/discovery-governance-valid.json`
- `validation/test_vectors/invalid/discovery-governance-missing-integrity.json`

This model covers well-known URI discovery, curated registry discovery, direct configuration, authenticated extended descriptors, restricted catalogs, freshness policy, integrity requirements, access policy, trust basis, and failure behavior.

### 2. Capability Negotiation Model

New artifacts:

- `docs/model/capability-negotiation.md`
- `schemas/tsmm-capability-negotiation.schema.json`
- `examples/capability-negotiation-instance.json`
- `validation/test_vectors/valid/capability-negotiation-valid.json`
- `validation/test_vectors/invalid/capability-negotiation-required-extension-missing.json`

This model separates advertised capability from discoverable, negotiated, authorized, executed, and evidenced capability. It also models extension URI, version, requiredness, opt-in, acceptance, rejection, and policy-bound outcomes.

### 3. Task Evidence Lifecycle Model

New artifacts:

- `docs/model/task-evidence-lifecycle.md`
- `schemas/tsmm-task-evidence-lifecycle.schema.json`
- `examples/task-evidence-lifecycle-instance.json`

- `validation/test_vectors/invalid/task-evidence-lifecycle-missing-receipt.json`

This model treats task state transitions as governance-relevant events. It requires authorization checkpoint evidence for `auth-required`, artifact references for `completed`, decision receipts for `rejected`, failure reasons for `failed`, and cancellation authority for `canceled`.

## Migration notes

This release is additive. No stable TSMM core schema fields are removed. Implementers can adopt the new discovery, capability negotiation, and task evidence lifecycle schemas independently.

Recommended migration path:

1. Keep existing TSMM core and graph examples unchanged.
2. Add discovery governance records for any agent/service descriptor used in authorization or routing.
3. Add capability negotiation records where advertised capabilities are policy-bound.
4. Add task evidence lifecycle records where tasks can produce operational effects.
5. Run the full validation suite.

## Enterprise assurance interpretation

v0.19.0 enables a stronger assurance posture for agentic systems because it makes the following independently inspectable:

- source and trust basis of discovery;
- descriptor integrity and freshness;
- disclosure policy for authenticated descriptor details;
- distinction between advertised and authorized capability;
- extension negotiation and required-extension failure handling;
- task lifecycle evidence for authorization, completion, rejection, failure, and cancellation;
- observability obligations for streaming, async, and push delivery;
- compensating controls for opaque agent internals.

## Known limitations

- This release does not define a wire protocol.
- This release does not claim conformance to A2A.
- Descriptor signing is modeled but not yet packaged as a dedicated signing profile.
- Evidence bundle packaging remains a candidate future increment.
- Human review and redress semantics are referenced but not yet fully modeled as a standalone lifecycle.
