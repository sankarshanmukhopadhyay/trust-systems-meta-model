# TSMS Stack 2026.1 — Cashew-Nut

**Release ID:** `tsms-stack-2026.1`  
**Codename:** Cashew-Nut  
**Status:** accepted for publication  
**Governing release gate:** [TSMM #19](https://github.com/sankarshanmukhopadhyay/trust-systems-meta-model/issues/19)

This is the first evidence-backed release of the Trust Systems Modelling Stack (TSMS). It packages an accepted cross-repository baseline together with a successful live wire transaction, deterministic falsification evidence, drift/renewal assurance, and adopter-facing guidance.

## Release proposition

The release demonstrates that a canonical delegated-authority transaction can traverse the accepted TSMM → TIS → TGA stack and produce an auditable decision only when semantic, contract, governance, authority, delegation, scope, evidence, and current-state requirements are satisfied.

## Falsification and fail-safe behavior

The release includes executable negative cases for missing authority, missing delegation, out-of-scope effects, missing evidence, non-current relationships, unresolved semantics, unavailable portable contracts, and absent executable governance binding.

At compatibility level, TSMS distinguishes:

- `UNCHANGED` — independently evidenced accepted state;
- `REVIEW_REQUIRED` — material drift; inherited compatibility withdrawn;
- `UNSUPPORTED` — outside the supported component/declaration contract;
- `INDETERMINATE` — authoritative evidence unavailable or unverifiable.

`INDETERMINATE` is not PASS.

## Drift and renewal assurance

The controlled assurance transaction demonstrates:

```text
accepted baseline
    ↓
successful wire / E2E execution
    ↓
material drift
    ↓
REVIEW_REQUIRED
    ↓
inherited compatibility withdrawn
    ↓
fresh owning-layer evidence
    ↓
rerun
    ↓
explicit acceptance
    ↓
compatibility restored
```

The renewal fixture is deliberately non-production. This release does not manufacture a successor production baseline receipt where no separately reviewed production state exists.
