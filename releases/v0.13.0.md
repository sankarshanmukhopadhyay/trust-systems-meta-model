# TSMM v0.13.0

## Release name

**Agent Interaction Extension**

## Summary

v0.13.0 adds a new extension layer for agent-to-agent interaction. The release is
shaped by a prima facie analysis of the A2A protocol (Agent2Agent, a2aproject/A2A) and
the question of whether TSMM should model additional aspects to remain genuinely useful
for A2A-class agent ecosystems while staying protocol-agnostic.

The answer was yes — but through extension-surface expansion rather than core
modification. Seven new trust-semantic abstractions are introduced, each with a paired
model document, all packaged in a new extension schema. No core model changes were
made. The effect-centered backbone, relationship model, and existing extension
architecture are unchanged.

The release also introduces two concepts — `OpacityBoundary` and `PeerTrustRelation`
— that go beyond what A2A itself makes explicit. These model trust-relevant invariants
that any protocol involving opaque agent-to-agent exchange must contend with, regardless
of the specific wire format.

## Additions

**Schema**
- added `schemas/tsmm-agent-interaction-extension.schema.json` — new extension schema
  defining seven abstractions: `serviceDescriptor`, `skillContract`, `peerTrustRelation`,
  `interactionContext`, `authorizationCheckpoint`, `opacityBoundary`, `extensionContract`

**Example**
- added `examples/agent-interaction-extension-instance.json` — two-party procurement
  workflow demonstrating all seven abstractions: buyer-side and supplier-side
  `serviceDescriptor` objects with different disclosure policies; two `skillContract`
  objects scoping capability authorization; a `peerTrustRelation` with
  `credential-exchange` trust basis; an `interactionContext` with inherited authority
  and re-authorization policy; an `authorizationCheckpoint` with `scope-exceeded`
  trigger; two `opacityBoundary` objects (one per agent); and two `extensionContract`
  objects recording SSE streaming acceptance and push-notification rejection

**Model documents**
- added `docs/model/service-descriptor.md` — trust-relevant capability disclosure
  artifact with policy-bound visibility and optional authenticity binding; generalizes
  A2A Agent Card, OpenID Federation entity statement, and TRQP ecosystem descriptor
- added `docs/model/skill-contract.md` — operational contract separating capability
  ("can do X") from authorized operational envelope ("may do X under these modalities,
  scope, and policy conditions")
- added `docs/model/interaction-context.md` — session-level governance state extending
  `ExecutionContext` to the multi-turn scope; models which authority and evidence carry
  forward and under what conditions re-authorization is required
- added `docs/model/authorization-checkpoint.md` — runtime authorization challenge as
  a first-class trust event; four trigger conditions: `policy-gap`, `auth-required`,
  `input-required`, `scope-exceeded`
- added `docs/model/extension-contract.md` — negotiated extension compatibility record;
  models silent downgrade as an audit gap requiring explicit governance record
- added `docs/model/opacity-boundary.md` — structural governance constraint modeling
  what is deliberately unobservable about an agent and what trust decisions can
  therefore claim; addresses the A2A foundational invariant that agents collaborate
  without exposing internal state, memory, or tools
- added `docs/model/peer-trust-relation.md` — lateral peer trust between agents with
  no pre-existing hierarchical relationship; structurally parallel to but distinct from
  `Delegation`; four trust basis types: `credential-exchange`, `capability-negotiation`,
  `policy-acceptance`, `third-party-introduction`

## Why this matters

TSMM already had the right backbone for this work: effect-centered design, entity and
role model, authority, policy, evidence, trust decisions, lifecycle events, agentic
extension, and multi-agent coordination. What was missing was an explicit surface for
the trust semantics of agent-to-agent interaction — specifically the concepts that
become first-class when two agents meet as peers rather than as principal and delegate.

**ServiceDescriptor and SkillContract** close the gap between "this agent exists" and
"this agent may do this thing under these conditions." Without that distinction, policy
evaluation over capabilities cannot be precise.

**InteractionContext** closes the gap between single-event trust decisions and
session-scoped governance. Multi-turn agent workflows depend on what was established
earlier; TSMM now has a place to model that state explicitly.

**AuthorizationCheckpoint** makes mid-interaction governance pauses a first-class trust
event rather than a transport state. The `scope-exceeded` trigger is especially
important for delegated-agent interactions reaching authority boundaries.

**ExtensionContract** makes extension negotiation auditable. Silent capability downgrade
without a governance record is a real audit gap in any extension-carrying protocol.

**OpacityBoundary** and **PeerTrustRelation** are the two abstractions that go beyond
what A2A itself makes explicit. OpacityBoundary addresses the governance consequence
of the opacity invariant: if an agent's internal state, tool set, and reasoning trace
are unobservable by design, trust decisions about that agent must be explicitly scoped
to what can actually be verified. PeerTrustRelation addresses the structural gap in
TSMM's existing delegation model: lateral peers with no hierarchical relationship
require a different trust basis mechanism than principal-to-sub-agent delegation.

## What this release does not include

Three abstractions from the release plan are deferred to v0.14.0:

- **InteractionTask** — deferred pending boundary investigation. Whether `ExecutionContext`
  plus lifecycle event composition already covers bounded work-in-progress semantics
  must be determined before committing to a new schema object.
- **ContentProvenancePolicy** — trust-policy envelope for interaction payload content;
  deferred to allow full extension shape to inform the scoping.
- **ObservabilityMode** — governance coverage constraints from delivery model
  (synchronous, streaming, polling, push-callback); deferred alongside
  ContentProvenancePolicy.

The A2A binding (`bindings/a2a/`) and A2A crosswalk (`docs/crosswalks/a2a-crosswalk.md`)
are also deferred to v0.14.0, when the full extension surface (including the three
above) will be available for mapping.
