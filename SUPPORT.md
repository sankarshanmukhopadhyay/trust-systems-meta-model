# Support

Use GitHub Issues for reproducible semantic ambiguities, validation defects, adoption questions, documentation gaps, and compatibility concerns. Include the TSMM version or commit, canonical concept/artifact involved, minimal example or counterexample, validation command where applicable, observed result, and expected semantic behavior.

For security-sensitive reports, follow [`SECURITY.md`](SECURITY.md) and do not publish exploit details in a public issue.

Support guidance does not create semantic authority. TSMM owns canonical trust-system meaning; TIS owns portable contracts; TGA and other downstream repositories own their project-local executable interpretations. Questions that reveal a missing or ambiguous concept should be resolved at the layer that owns that proposition.
